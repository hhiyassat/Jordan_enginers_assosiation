# RC-05 · Worktree Cleanliness

Foundation program reported `TRACKED_WORKTREE_CLEAN=NO` with the single tracked modification `backend/bootstrap/cache/services.php`. This closure inspects and repairs.

## Investigation

### Is it tracked?

```
$ git ls-files -- backend/bootstrap/cache/services.php
backend/bootstrap/cache/services.php
$ echo "exit=$?"
exit=0
```

Yes — the file is tracked in the repository.

### Why does it change?

Laravel's package-discovery cache. Regenerated by:

* `composer install` / `composer update`
* `php artisan package:discover --ansi` (auto-run by composer post-install)
* `php artisan config:cache` / `php artisan optimize`

Every `composer install` in the repo rewrites this file with the current package list. This is a non-deterministic write (order can vary).

### Does repository policy expect it committed?

**No.** `backend/.gitignore` line 8:

```
bootstrap/cache/*.php
```

The gitignore explicitly excludes this pattern. The file was tracked because it was committed at the initial commit **before** the gitignore rule was added (verified: `git log --oneline -- backend/bootstrap/cache/services.php` returns only `9399b45 Initial commit`).

### Repair

`git rm --cached backend/bootstrap/cache/services.php` — removes from tracking while preserving the file on disk (Laravel needs it at runtime). After the commit, future regenerations no longer show in `git status` because the file now matches the pre-existing `.gitignore` rule.

## Change

Single deletion from the index:

```
D  backend/bootstrap/cache/services.php
```

File remains on disk:

```
$ ls backend/bootstrap/cache/services.php
backend/bootstrap/cache/services.php
```

## Behaviour going forward

* Every `composer install` continues to rewrite the file — no `git status` noise.
* Any developer who pulls this commit will see the file drop from the index; their local file remains.
* CI is unaffected (CI regenerates the file post-composer, has always had this file present).
* No functional runtime change.

## Result

`TRACKED_WORKTREE_CLEAN=YES` after the RC-05 commit — verified by `git status --porcelain` showing only user-owned untracked entries (`??` prefixed) and the two intentional tracked changes of this phase (the deletion of the cache and this closure's own RC-04+RC-05 report additions).
